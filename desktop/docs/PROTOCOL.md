# Desktop worker protocol v1

One UTF-8 JSON request is written to stdin; the process returns UTF-8 JSON-lines events on stdout. Standard input is then closed. Human-readable package output is redirected into progress events. Errors produce an `error` terminal event and nonzero exit code; success produces exactly one `completed` terminal event and exit code zero. A missing or malformed terminal response is a failure in C#.

Request fields: `protocol_version` (1), `request_id`, `action` (`catalog`, `inspect`, `run`), `module_id`, `dataset` (absolute path or `demo`), `target`, `output_root` (absolute path), and module-specific `settings`. Tabular settings are `models` (ids; classification also accepts the older name `classifiers`), `validation` (`auto`, `holdout`, `kfold5`, `kfold10`; classification also `stratified`, `loo`), `selection` (`auto`, `nested`, `final_test`), and `figures` (boolean).

Every event repeats `protocol_version` and `request_id`. Progress carries `message` and optionally `session_dir`. Completion carries `result`; errors carry `message` and a diagnostic `detail`. The GUI shows the short message and retains detail in its activity log. Request ids are verified to prevent associating another job's result with the current operation.

Catalog returns real installed modules with model descriptors, metric descriptors (`key`, `label`, `format`: `percent`, `decimal3`, `decimal4` or `number`), the `headline` metric keys, `validation_options`, `selection_options` and interface `labels` (target title and hint, models title, model noun, example button, preparation note). The interface reads these instead of assuming a task. Inspection returns counts, target suggestion, column descriptions with `suitable` and `note` for the module's task, and eight preview rows. Completion of either module also returns `selection_metric`, a plain-language `summary`, and `figures` (`key`, `title`, `caption`, `path` of the PNG). Comparison rows carry `selection_score`, `note` and `reference` (true for regression's predict-the-average row, which is also returned as `baseline`). Classification completion returns full-precision `final` metrics, a separately labelled `comparison` list, the selected classifier, evaluation method, sample counts, class order, output artifacts and environment versions. A final score under nested CV belongs to the selection procedure, while the selected classifier is the model refitted for saving.

Cancellation is owned by the desktop process client. It kills the worker and descendants and raises cancellation without consuming any partial result. The GUI marks a known session as cancelled. A terminal completion is accepted only after both the protocol and process exit code indicate success.

## Additions in desktop 0.3

Still protocol version 1; every addition is optional, so older modules keep working.

* Catalog: `file_filter` (the Browse dialog's file types for the module) and, for a module that could not be loaded, `unavailable_reason` (plain words; the module is listed with its `id`, `title` and `description` only). Empty `validation_options` and `selection_options` hide the evaluation settings (forecasting).
* Inspection: `parameters`, a list of data-dependent choices, each with `id`, `label`, `hint`, `options` (`id`, `name`) and `default`; the desktop shows them as drop-down lists and sends each chosen `id` in `settings` under the parameter's `id`. `advice`, a list of plain-language sentences about the data.
* Completion: `evaluation_text`, a plain description of the final evaluation that replaces the generic one; `tables`, extra result tables (`title`, `hint`, `columns`, `rows` as text), such as the forecast.
* Errors: `message` is one plain sentence (known problems such as empty, damaged or locked files are translated); `detail` keeps the full traceback.
* The worker reads and writes UTF-8 whatever the console code page.
* Progress events may carry `fraction` (0-1), the share of the analysis done, estimated by the module from its expected steps; it never decreases and stays below 1 until completion. A progress event with an empty `message` only updates the fraction (deep-learning epochs) and is not logged.
* Catalog: `advanced_choices` (drop-down choices, the same shape as `parameters`) and `advanced_lists` (tick lists: `id`, `label`, `hint`, `options` and `default`, the list of option ids ticked at first), shown in the closed **Advanced options** section with the defaults preselected. The run request sends each choice's option `id` and each list's ticked ids (an array of strings) in `settings` under the `id`. Settings that are left out keep the usual behaviour; a figure list equal to its `default` means "automatic", so figures added only when the data call for them are still added. Ids used by the four modules: `figure_keys`, `figure_theme`, `figure_format` (all); `metrics`, `knn_distance`, `knn_k`, `missing`, `encoding`, `scaling` (classification). Unknown values are refused with a plain message before the analysis starts.
